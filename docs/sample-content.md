# 从零开始搭建个人博客——Ghost 入门指南

在这个信息爆炸的时代，拥有一个属于自己的博客是一件非常有意义的事情。本文将带你从零开始，使用 Ghost 搭建一个功能完整的个人博客。

## 为什么选择 Ghost？

Ghost 是一个专注于博客和内容创作的开源平台，具有以下优势：

- **简洁专注**：界面简洁，专注于写作体验

- **开源免费**：MIT 许可证，可自由使用和修改

- **功能丰富**：会员系统、评论、邮件订阅一应俱全

- **主题生态**：丰富的主题市场，支持自定义开发

## 环境准备

在开始之前，你需要准备以下环境：

- Node.js（推荐 v18 或 v20 LTS）

- npm 或 yarn 包管理器

- Git 版本控制工具

```bash
# 检查 Node 版本
node --version

# 检查 npm 版本
npm --version

# 安装 Ghost CLI
npm install -g ghost-cli
```

## 安装 Ghost

使用 Ghost CLI 可以快速完成本地安装：

```bash
# 创建项目目录
mkdir my-blog && cd my-blog

# 本地安装
ghost install local

# 启动 Ghost
ghost start
```

安装完成后，访问 `http://localhost:2368/ghost/` 完成管理员初始化。

## 下一步

完成基础安装后，你可以：

1. 选择或定制主题
2. 创建第一篇文章
3. 配置会员系统
4. 启用评论功能

希望这篇指南对你有帮助！祝你在博客写作的路上越走越远。

### 文章 2：开源软件二次开发的边界与思考

- **标签**：开源分享

- **封面图**：有

- **摘要**：探讨在开源项目基础上进行二次开发时，如何合理界定修改边界，既满足业务需求又保持升级能力。

**正文内容：**

# 开源软件二次开发的边界与思考

开源软件的繁荣让我们可以站在巨人的肩膀上快速构建产品。但二次开发并非简单地"拿来就改"，如何把握好修改边界，是每个开发者都需要思考的问题。

## 为什么要关注边界？

1. **升级成本**：修改核心代码越多，版本升级成本越高
2. **维护难度**：偏离主线越远，社区资源越难复用
3. **许可证合规**：不同许可证对修改和分发有不同要求
4. **团队协作**：清晰的边界让团队分工更明确

## 常见的修改策略

### 策略一：主题/模板层修改

适用于博客、CMS 等系统。只修改前端展示层，不动核心逻辑。

**优点**：升级影响小，安全性高
**缺点**：功能受限，只能做展示层改动

### 策略二：API/插件扩展

利用官方提供的插件机制、API 接口进行功能扩展。

**优点**：升级友好，遵循官方规范
**缺点**：受限于 API 设计，某些需求可能无法实现

### 策略三：伴随服务

独立部署一个微服务，通过 API 与主系统交互。

**优点**：完全解耦，技术栈自由
**缺点**：部署复杂度增加，数据一致性需要考虑

### 策略四：核心修改

直接修改核心源代码。

**优点**：功能实现最灵活
**缺点**：升级困难，维护成本高

## 实践建议

1. **优先使用官方扩展机制**：插件、主题、API
2. **核心改动最小化**：非必要不改核心
3. **做好版本锁定**：固定依赖版本，避免意外升级
4. **保留升级路径**：定期评估升级可行性
5. **文档化修改内容**：清晰记录哪些是自定义改动

## 结语

二次开发的艺术在于平衡——平衡需求与维护、定制与升级、速度与质量。希望每个开发者都能在开源的世界里找到属于自己的最佳实践。

# SQLite 轻量级数据库入门与实践

SQLite 是世界上使用最广泛的数据库引擎。它轻量、快速、零配置，是小型应用和嵌入式系统的理想选择。

## 什么是 SQLite？

SQLite 是一个**嵌入式数据库**，它的数据库就是一个文件，不需要单独的服务器进程。应用程序通过调用 SQLite 库直接读写数据库文件。

### 特点

- **零配置**：无需安装和配置

- **单文件**：整个数据库就是一个文件

- **跨平台**：支持 Windows、Linux、macOS

- **事务支持**：ACID 事务保证

- **开源免费**：公共领域，可自由使用

## 基本命令

```sql
-- 创建表
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT NOT NULL UNIQUE,
    email TEXT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 插入数据
INSERT INTO users (username, email)
VALUES ('zhangsan', 'zhangsan@example.com');

-- 查询数据
SELECT * FROM users WHERE username = 'zhangsan';

-- 更新数据
UPDATE users SET email = 'new@example.com' WHERE id = 1;

-- 删除数据
DELETE FROM users WHERE id = 1;
```

## 常用场景

1. **桌面应用**：本地数据存储
2. **移动应用**：App 内嵌数据库
3. **开发测试**：快速原型验证
4. **小型网站**：低流量博客和 CMS
5. **物联网设备**：嵌入式数据存储

## Ghost 中的 SQLite

Ghost 本地开发模式默认使用 SQLite 作为数据库，数据库文件位于：
`content/data/ghost-local.db`

可以使用 SQLite 命令行工具查看数据库：

```bash
sqlite3 content/data/ghost-local.db

-- 查看所有表
.tables

-- 查看表结构
.schema posts

-- 查询文章
SELECT id, title, slug FROM posts LIMIT 5;
```

## 注意事项

1. **并发写入**：SQLite 支持并发读，但写操作是串行的
2. **大规模数据**：数据量超过 100GB 时考虑其他数据库
3. **网络文件系统**：不建议在 NFS 等网络文件系统上使用
4. **备份**：直接复制数据库文件即可完成备份

SQLite 虽小，但功能强大。掌握它，你会发现很多场景下它都是最佳选择。

### 文章 5：Handlebars 模板引擎入门教程

- **标签**：技术笔记

- **封面图**：有

- **摘要**：Handbars 是一款流行的 JavaScript 模板引擎，Ghost 主题就是基于它开发的。本文带你快速上手。

**正文内容：**

# Handlebars 模板引擎入门教程

如果你想开发 Ghost 主题，Handlebars 是绕不过去的技术。它是一款语义化的模板引擎，语法简洁，功能强大。

## 什么是 Handlebars？

Handlebars 是 Mustache 模板语言的扩展，增加了更多功能。它使用 `{{ }}` 语法来插入变量，让模板代码更加清晰易读。

## 基础语法

### 变量输出

```handlebars
<p>Hello, {{name}}!</p>
```

如果数据是 `{name: "World"}`，输出结果为：

```html
<p>Hello, World!</p>
```

### HTML 转义

默认情况下，Handlebars 会对 HTML 进行转义，防止 XSS 攻击。如果需要输出原始 HTML，使用三个花括号：

```handlebars
{{{htmlContent}}}
```

### 注释

```handlebars
{{! 这是注释，不会输出 }}
```

## 块级表达式

### if-else

```handlebars
{{#if isLoggedIn}}
  <p>欢迎回来，{{username}}！</p>
{{else}}
  <p>请先登录</p>
{{/if}}
```

### each 遍历

```handlebars
<ul>
  {{#each posts}}
    <li>
      <a href="{{url}}">{{title}}</a>
    </li>
  {{/each}}
</ul>
```

在 each 块中，可以使用 `this` 引用当前项：

```handlebars
{{#each tags}}
  <span>{{this.name}}</span>
{{/each}}
```

### unless（反向 if）

```handlebars
{{#unless comments}}
  <p>暂无评论</p>
{{/unless}}
```

## 助手函数（Helpers）

Handlebars 允许自定义助手函数来扩展模板功能。Ghost 内置了很多有用的助手：

```handlebars
{{! 日期格式化 }}
{{date published_at format="YYYY年MM月DD日"}}

{{! 截断文字 }}
{{excerpt characters="100"}}

{{! 翻译 }}
{{t "Read more"}}
```

## 局部模板（Partials）

把常用的模板片段抽成 partial，方便复用：

```handlebars
{{!-- 引入 partial --}}
{{> "post-card"}}
```

partial 文件放在 `partials/` 目录下，文件名就是 partial 名。

## Ghost 主题中的应用

Ghost 主题大量使用 Handlebars：

- `default.hbs` - 主布局模板

- `index.hbs` - 首页模板

- `post.hbs` - 文章详情模板

- `tag.hbs` - 标签页模板

- `author.hbs` - 作者页模板

- `partials/` - 可复用的模板片段

掌握 Handlebars 是定制 Ghost 主题的第一步。多写多练，很快就能上手！

### 文章 7：开源贡献新手村——第一次提交 PR 全记录

- **标签**：开源分享

- **封面图**：有

- **摘要**：记录我第一次为开源项目贡献代码的完整过程，从 fork 到合并，踩过的坑都在这里。

**正文内容：**

# 开源贡献新手村——第一次提交 PR 全记录

很多人想参与开源贡献，但不知道从何入手。本文记录我第一次提交 PR 的完整过程，希望能帮到同样想入门的你。

## 准备工作

### 1. 选择项目

第一次贡献建议选：

- 自己正在使用的项目（有使用经验更容易理解问题）

- 社区活跃，维护者友好

- 有 "good first issue" 标签的项目

我选择的是一个 Ghost 主题项目，正好自己在用，对功能也比较熟悉。

### 2. 环境准备

```bash
# Fork 项目到自己的 GitHub
# 然后克隆到本地
git clone https://github.com/你的用户名/项目名.git

# 添加上游仓库
git remote add upstream https://github.com/原作者/项目名.git

# 安装依赖
npm install
```

### 3. 找到合适的 Issue

项目的 Issue 列表里找 "good first issue" 或 "help wanted" 标签。我选的是一个修复小 bug 的 issue。

## 开发过程

### 1. 创建分支

```bash
# 确保主分支是最新的
git checkout main
git pull upstream main

# 创建功能分支
git checkout -b fix/typo-in-readme
```

分支命名建议：

- `feature/xxx` - 新功能

- `fix/xxx` - Bug 修复

- `docs/xxx` - 文档更新

### 2. 编写代码

按照项目的代码风格来写。修改前先看看现有的代码是怎么写的，保持一致。

### 3. 测试

```bash
# 运行项目测试
npm test

# 如果有 lint 检查
npm run lint
```

确保所有测试通过，不要引入新问题。

### 4. 提交代码

```bash
git add .
git commit -m "fix: correct typo in README

- fix typo in installation section
- update example command"
```

Commit message 规范很重要，推荐 Conventional Commits 格式。

### 5. 推送并创建 PR

```bash
git push origin fix/typo-in-readme
```

然后在 GitHub 页面点击 "Compare & pull request"。

## 写好 PR 描述

一个好的 PR 描述应该包含：

1. **背景**：为什么要做这个修改？关联哪个 issue？
2. **改动**：具体改了什么？
3. **测试**：如何验证修改是正确的？
4. **截图**：如果是 UI 改动，附上前后对比图

示例：

```
## 问题
修复 README 中安装命令的拼写错误（closes #123）

## 改动
- 将 `npm isntall` 改为 `npm install`
- 更新了示例输出

## 验证
- [x] 本地运行 npm install 成功
- [x] 所有测试通过
```

## 等待 Review

提交 PR 后耐心等待维护者 review。可能会有修改意见，这很正常。

收到反馈后：

1. 感谢对方的 review
2. 按照意见修改代码
3. 推送新的 commit（不要 force push）
4. 回复说明已修改

## 合并！

当 PR 被合并的那一刻，真的很有成就感！你的代码从此成为了开源世界的一部分。

## 常见问题

### Q: 我不会写复杂的代码，能贡献什么？

A: 当然可以！文档改进、错别字修复、翻译、Bug 反馈都是贡献。从小处着手，慢慢积累。

### Q: 怕自己写得不好被笑话

A: 不会的。开源社区欢迎新手，维护者们大多很友好。认真的贡献都会被尊重。

### Q: 等了很久没人 review 怎么办？

A: 可以礼貌地 ping 一下维护者。开源项目维护者都是用业余时间在做，多一份理解。

## 结语

第一次贡献可能会紧张，但迈出第一步后就会发现其实没那么难。开源社区欢迎每一个想要贡献的人。

## 操作步骤

### 第一步：创建标签

1. 进入后台 → Posts → Tags
2. 点击 "New tag"
3. 依次创建 3 个标签

### 第二步：创建会员

1. 进入后台 → Members
2. 点击 "New member"
3. 填入邮箱和姓名
4. 保存

### 第三步：发布文章

1. 进入后台 → Posts → New post
2. 填写标题和正文
3. 设置标签、封面图、摘要
4. 点击 Publish 发布

### 第四步：启用评论和会员功能

1. 进入后台 → Settings → Membership
2. 开启会员注册功能
3. 进入 Settings → Comments
4. 设置评论权限（建议：所有会员可评论）
